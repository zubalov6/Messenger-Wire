# Wire — фронтенд мессенджера

Фронтенд на Vite + React для FastAPI-бэкенда (JWT-аутентификация, чаты, сообщения, WebSocket).

## Запуск

```bash
npm install
cp .env.example .env   # укажите адрес вашего FastAPI-сервера в VITE_API_URL
npm run dev
```

По умолчанию `.env` указывает на `http://localhost:8000`. WebSocket-адрес выводится из `VITE_API_URL` автоматически (`http` → `ws`, `https` → `wss`).

## Что реализовано

- Регистрация и вход (`/register`, `/login`), хранение JWT в `localStorage`, автоматическая проверка сессии через `/me`.
- Список чатов (`/chats`), создание личного чата по ID пользователя (`/chats/direct`) и создание группы с указанием названия и ID участников (`/chats/group`).
- Просмотр сообщений с подгрузкой более старых через курсор `before` (`/chats/{id}/messages`), отправка сообщений, поиск по чату (`/chats/{id}/messages/search`).
- Живая доставка сообщений через `/ws/chats/{id}` с fallback на обычный POST, если сокет не подключён.
- Панель участников группы: список с ролями, добавление и удаление участников (только для админа чата) через `/chats/{id}/members`.
- Адаптивная раскладка: список чатов и диалог переключаются как отдельные экраны на мобильной ширине.

## Известное ограничение бэкенда

В API нет эндпоинта поиска пользователей по логину — добавление участника в чат и создание личного чата возможны только по числовому `user_id`. Поэтому в интерфейсе эти формы просят ввести ID, а не логин. Если на бэкенде появится поиск пользователей (например, `GET /users?query=`), это легко заменить на автодополнение по логину.

## Структура

```
src/
  api/            fetch-обёртки к эндпоинтам бэкенда
  context/        AuthContext — сессия и токен
  hooks/          useChatSocket — WebSocket-подключение к чату
  components/      Sidebar, ConversationView, MessagesList, Composer, MembersPanel, NewChatPanel
  pages/          LoginPage, RegisterPage, ChatPage
  styles/         auth.css, chat.css — токены и стили
```
